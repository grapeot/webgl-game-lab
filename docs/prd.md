# 产品需求文档（PRD）：webgl-game-lab

## 1. 背景与目标

Unity IL2CPP WebGL 游戏在浏览器中运行于 `wasm32` 线性内存（HEAP）之上，常规 DOM 检查或顶层脚本扫描只能看到前端加载器与容器外壳，无法直接观测局内状态、计时器、轨道几何或障碍生成规律。当游戏包含付费入场机制时，靠反复重开局调试还会产生额外消耗。

`webgl-game-lab` 面向已登录的本地 Chrome DevTools Protocol（CDP）浏览器会话，提供一套命令行工具（`webgl-lab`）与配套 Agent Skill，用于内存状态发现、只读运行轨迹采集、赛道与障碍预计算，以及经显式授权的单局倒计时锁定实验。当前适配 `Moe.Ski.SkiSoloGame`；机制已由手工原型真实对局验证，新 CLI 的验证层级见 `working.md`。

## 2. 核心结论与产品边界

| 维度 | 支持范围 | 明确排除项 |
|---|---|---|
| 目标运行时 | Unity IL2CPP WebGL（`wasm32`），类名与字段名未经混淆的 `Moe.Ski.SkiSoloGame` 适配器 | 任意 Unity 版本的盲改、符号已混淆包的自动逆向、万能游戏外挂 |
| 浏览器管理 | 连接用户自备且已手动登录的 CDP 浏览器标签页（如 `http://127.0.0.1:9222`） | 启动或关闭浏览器、托管账号凭证、自动创建付费对局 |
| 观测能力 | 顶层 JS/实例清单检查、IL2CPP 类与 `FieldInfo` 动态解析、存活实例状态、赛道几何与障碍预测、可选网络数值元数据 | 默认抓取完整网络载荷、导出 Cookies/Token/昵称/UID、把加载器外层脚本说成游戏核心逻辑 |
| 修改能力 | 用户显式执行 `hold` 时调节当前唯一存活实例的 `roundDuration`，`release`/`stop` 时平顺恢复倒计时 | 自动开局、充值、买道具、改分数、领奖励、发弹幕、向服务端伪造提交成绩 |
| 产物落盘 | 脱敏 JSON 轨迹与可选运行时 WASM 字节码默认写入本地 `.local/` 目录 | 将游戏资产、WASM、截图或会话数据提交至版本库 |

## 3. 目标用户与使用场景

1. **WebGL 运行时观测与关卡研究**：开发者或分析人员借助 AI Agent 连接本地浏览器，读取当前活动对局的坐标、速度、时间字段以及赛道 `runtimePoints` / `runtimeTangents` 数据，分析基于 `seed` 和 `map` 模板的障碍分布。
2. **受控计时实验**：在不冻结 Unity 主循环与物理运动的前提下，单局延长 `roundDuration` 以完成长距离赛道观测，并在实验结束时通过 `release` 从当前剩余秒数平顺恢复倒计时。
3. **付费对局前的离线与静态准备**：在用户实际消耗入场资格前，先完成适配器检查、字段偏移核验与采集脚本就绪，避免拿付费重跑充当调试手段。

## 4. 功能需求

### 4.1 目标连接与顶层检查（`targets` / `inspect`）
- 支持通过 `--cdp`（或环境变量 `WEBGL_CDP_URL`，默认示例 `http://127.0.0.1:9222`）列举浏览器标签页。
- 支持通过 `--match`（或环境变量 `WEBGL_TARGET_MATCH`，示例 `game.example.com`）或显式 `--target <id>` 绑定目标页面。
- `inspect` 只读枚举页面顶层 JS 对象、Unity 实例入口与脚本清单，明确区分外层加载器与核心游戏逻辑。

### 4.2 动态符号发现与存活实例校验（`preflight` / `discover`）
- `preflight` 仅检查元数据，可在无活动实例时运行；采集器可以等待实例出现。
- 在已加载的 IL2CPP HEAP 中动态定位 `Moe.Ski.SkiSoloGame` 类结构，通过 `FieldInfo` 解析字段偏移，不硬编码进程内存地址。
- 校验托管实例的 `native` 指针非 0、初始化标志、单局时长、坐标合理性及唯一性。当 HEAP 中残留已销毁旧实例（`native = 0`）或存在多实例歧义时，拒绝绑定修改操作。

### 4.3 只读采集、状态与地图解析（`install` / `status` / `map` / `export` / `wasm-export`）
- `install` 默认安装只读状态采样器；附加 `--network` 时，仅记录 WebSocket 与 `fetch` 的数值测量及命令种类，剥离请求/响应正文、凭证与身份信息。
- `status` 返回当前唯一存活实例的实时计时（`roundDuration`、`elapsedSeconds`、剩余时间）、位置坐标与运行状态。
- `map` 读取赛道 `runtimePoints` 与 `runtimeTangents`，结合当前实例的 `seed` 与 `map` 编号输出确定性障碍预测序列。
- `export` 将脱敏后的结构化采样轨迹输出至 `.local/`（如 `.local/run.json`）。
- `wasm-export` 按需将浏览器当前已加载的运行时 WASM 字节码导出至 `.local/game.wasm` 供离线分析，不还原原始 C# 源码，也不随项目分发。

### 4.4 单局倒计时控制（`hold` / `release` / `stop`）
- `hold` 仅在验证当前存在唯一存活实例后，通过拉长 `roundDuration` 锁定客户端显示的剩余倒计时，保持物理与位置更新正常推进；对局实例销毁或重建后自动失效，不跨局继承。
- `release` 清除锁时状态并保留最近写入的 `roundDuration` 截止线，使倒计时从当前剩余秒数继续递减，避免恢复初始 180 秒导致对局立刻结束。
- `stop` 停止后台采集器，同时执行倒计时释放逻辑。

## 5. 验收标准

1. **唯一存活实例验证**：任何状态读取与计时修改必须建立在 `native != 0` 且通过字段合理性校验的唯一活动实例之上；旧局残留实例不触发误绑。
2. **锁时与释放双重核验**：执行 `hold` 后，连续两次不同时间点的采样必须显示 `position` 与 `elapsedSeconds` 持续增长，而剩余时间基本恒定，并与页面 UI 显示一致；执行 `release` 后，剩余时间从当前值继续下降（例如实测从约 59 秒平顺降至 53 秒）。
3. **地图确定性边界**：给定同一版本的 `seed` 与 `map` 模板编号，障碍横坐标与树类别可完整复算；跨场次或游戏版本更新后必须重新执行 `discover` 与 `map` 读取。
4. **服务端结算客观表述**：客户端修改 `roundDuration` 仅影响本地倒计时判定；服务端是否接受修改后的成绩需独立验证，工具与文档不宣称已绕过服务端结算校验。
5. **输出与仓库洁净度**：CLI 统一返回结构化 JSON，本地导出物落入 `.local/`，版本库仅保留原创工具源码、合成测试与公开文档。
