## 2. 已核实匿名技术摘要

### 2.1 实例生命周期与计时控制
- **字段类型与默认值**：在目标 `Moe.Ski.SkiSoloGame` 运行时中，单局总时长 `roundDuration` 为 `float32`（默认 `180` 秒），已进行时间 `elapsedSeconds` 为 `float64`。
- **内部 Getter 验证（手工原型）**：在已结束对局将 `roundDuration` 临时修改为 `360` 秒时，游戏自身剩余时间 getter 返回 `180` 秒，随后还原。
- **活动局锁时与释放实测（手工原型）**：
  - 在唯一存活实例（`native != 0`）运行期间启动 `hold`，客户端剩余时间稳定保持在约 `59` 秒，同时角色坐标（`position`）与 `elapsedSeconds` 持续增长。
  - 执行 `release` 将截止线固定后，剩余时间未跳回初始 180 秒，而是从 `59` 秒平顺递减至 `53` 秒。

### 2.2 赛道几何与障碍生成规律
- **赛道采样**：单局实测读取 `runtimePoints` 共 `352` 个采样点，终点横坐标为 `7000`，同时可读取对应的 `runtimeTangents` 切线数组。地形点阵在局初完成生成。
- **障碍坐标与树类别公式**：
  - 存在 3 套障碍模板参数，`spacing` 三档为 `44` / `38` / `42`，`jitter` 模数三档为 `25` / `19` / `23`，首障碍偏移 `offset = 55`。
  - 对第 `i` 个障碍，按 32 位无符号整数计算：
    `h = imul(i, 374761393) + imul(seed, 668265263)`
    `h = imul((h >>> 13) ^ h, 1274126177)`
    `h = (h >>> 16) ^ h`
    `x = startX + 55 + i * spacing + (h % jitter)`（`h` 全程按 32 位无符号整数处理）。
  - 树类别判定：`map 1` 采用 `h % 4`，`map 2` 采用 `h % 3`，其余模板采用 `h % 5`，余数为 `0` 时生成树。
   - 只要当前局的 `seed` 与 `map` 确定，就可按本版本公式预测障碍分布；跨场次可能改变或重复，必须重新读取。

## 3. 已识别技术陷阱与修正措施

1. **外层脚本与核心逻辑区分**：顶层 HTML/JS 仅包含 Unity WebGL 加载器，不能将读取加载器算作已读懂游戏逻辑；核心机制必须通过 WASM 函数体、IL2CPP 元数据与运行态内存读数交叉核实。
2. **HEAP 残留旧实例与局号重置**：对局结束后旧托管实例仍留在线性内存中，单凭指针非 0 或类名匹配会产生误判，必须检查 `native != 0`（`native = 0` 代表已销毁）。此外新开场次会将局号重置为 `1`，不能依赖局号变化判断实例切换，每次修改前都必须重新锁定当前唯一存活实例。
3. **UI 面板位移导致静态裁剪失效**：游戏内面板位置变化会让固定像素坐标截图裁剪失准，验证时应优先读取实例状态并结合 DOM 边界定位。
4. **全局暂停与锁倒计时的区别**：暂停 Unity 主循环会让角色运动一并停止；锁倒计时应只顺延 `roundDuration`，保持物理运动正常推进。
5. **客户端锁时与服务端结算边界**：本地延长 `roundDuration` 不代表服务端认可超时成绩，服务端结算验收仍处于待独立验证状态。
6. **大体积 WASM 的按需反编译**：已加载的运行时 WASM 约 `42MB`，分析时只提取并反编译目标函数体，避免全量反编译生成巨型文本。

## 5. Lessons Learned

- 工具进程存活不等于绑定对象仍存活；必须验证 native 指针与唯一实例。
- 保留别人的函数包装器时，也要停用自己的旧包装器逻辑，否则停止命令只改了表面状态。
