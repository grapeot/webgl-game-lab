# `Moe.Ski.SkiSoloGame` 运行时参考（Unity IL2CPP WebGL wasm32）

本文档记录 `Moe.Ski.SkiSoloGame` 的技术规格及手工原型实测事实，供 [`SKILL.md`](../SKILL.md) 按需加载。原型实测不等于重构 CLI 的端到端验收；分层验证记录见项目 `docs/working.md`。跨版本更新后必须重新预检并核实算法。

## 1. IL2CPP 内存发现与存活实例判据

### 1.1 动态元数据解析
- **目标类**：命名空间 `Moe.Ski`，类名 `SkiSoloGame`。
- **字段定位**：通过遍历 IL2CPP 运行时类型元数据与 `FieldInfo` 结构动态读取字段偏移，不在工具中硬编码进程或堆指针。
- **外层与核心区分**：页面顶层 JS 与 HTML 脚本仅负责加载 Unity WebGL 实例；真实计时、物理更新与赛道生成均在 `wasm32` 模块内执行。

### 1.2 存活实例过滤规则
对局重开或跨场切换后，已结束对局的托管实例依然残留在 IL2CPP HEAP 中。单凭托管对象指针非 0 或类名匹配会把死亡实例误认为当前对局，导致「假锁」。判定当前唯一存活实例必须同时满足：
1. **`native != 0`**：托管对象内部的底层 C++ 指针非 0（`native = 0` 代表对象已销毁）。
2. **状态与数值合理性**：初始化标志已置位，单局时长、已用时间与角色坐标位于有效区间。
3. **不依赖局号变化**：新建场次会将局号重置为 `1`，不能靠局号递增识别新局，每次操作前均须重新扫描并确认唯一存活对象。
4. **唯一性门禁**：当且仅当匹配到唯一存活实例时才允许 `hold` / `release`；出现 0 个或多个候选实例时直接报错并拒绝写入。

## 2. 计时字段与锁时/释放机制

### 2.1 核心时间字段
| 字段含义 | 存储类型 | 默认/实测行为 |
|---|---|---|
| `roundDuration`（单局总时长） | `float32` | 默认 `180.0` 秒 |
| `elapsedSeconds`（已进行时间） | `float64` | 随对局进行单调递增 |
| 剩余时间（内部 getter） | 计算值 | 由 `roundDuration` 与 `elapsedSeconds` 差值决定；实测将 `roundDuration` 临时改为 `360` 时，内部 getter 立即返回剩余 `180` 秒（验证后已还原） |

### 2.2 锁时（`hold`）与释放（`release`）行为
- **`hold`**：不冻结 Unity 全局时间或物理循环，仅对当前唯一存活实例顺延 `roundDuration`。实测在活动局中可将剩余时间稳定保持在约 `59` 秒，同时角色坐标（`position`）与 `elapsedSeconds` 正常增长。若实例销毁或进入下一局，锁时自动解除。
- **`release`**：若在超时后直接把 `roundDuration` 改回 `180` 秒，剩余时间会立即归零。实现清除锁时状态，保留最近写入的截止值，倒计时继续递减。手工原型实测从 `59` 秒降至 `53` 秒；新 CLI 已有离线回归，活动局端到端待验证。
- **服务端结算说明**：客户端延长 `roundDuration` 不代表服务端认可超时成绩；服务端是否接受修改后的分数需独立验证。

## 3. 赛道几何与障碍预计算算法

### 3.1 赛道曲线数据
- 存活实例中保存有 `runtimePoints`（赛道采样点数组）与 `runtimeTangents`（切线数组）。
- 在当前已核实的实测样本中，`runtimePoints` 共包含 `352` 个点，终点横坐标为 `7000`。地形点阵通常在对局初始化时一次性生成。

### 3.2 障碍位置与树类别哈希公式
当前版本包含 3 套障碍分布参数模板：
- 间距 `spacing` 三档：`44`、`38`、`42`
- 抖动模数 `jitter` 三档：`25`、`19`、`23`
- 首障碍偏移固定值：`offset = 55`

给定当前局的 `seed`、模板参数及起点横坐标 `startX`，第 `i` 个障碍（$i \ge 0$）通过 32 位无符号整数（unsigned 32-bit）哈希计算：

```javascript
// h 全程按 32 位无符号整数（>>> 0）处理
let h = (Math.imul(i, 374761393) + Math.imul(seed, 668265263)) >>> 0;
h = Math.imul((h >>> 13) ^ h, 1274126177) >>> 0;
h = ((h >>> 16) ^ h) >>> 0;

const x = startX + 55 + i * spacing + (h % jitter);
```

树类别判定规则（按当前局 `map` 编号取模，余数为 `0` 时生成树）：
- `map == 1`：`h % 4 === 0`
- `map == 2`：`h % 3 === 0`
- 其余情况：`h % 5 === 0`

### 3.3 确定性与跨场边界
- 「3 套模板」并不代表每局完全不可预测：只要在局内读取到当前存活实例的 `seed` 与 `map`，即可完整预计算本局障碍坐标与树分布。
- 跨场次 `seed` 与 `map` 可能更换或重复，因此每场都必须重新读取，不能将单场预计算结果静态复用到后续场次。

## 4. WASM 字节码与 UI 核验注意事项

- **按需局部反编译**：通过 `wasm-export` 导出的浏览器运行时字节码体积约 `42MB`。离线核对算法时，只定位并反编译相关函数体，不要把整个 WASM 模块反编译为巨型文本。
- **优先实例读数与 DOM 边界**：游戏内悬浮面板移动会使固定像素坐标的截图裁剪失效，验证倒计时与状态时应优先使用实例内存读数并配合实时 DOM 边界。
